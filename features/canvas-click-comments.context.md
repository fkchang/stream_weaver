# Epic wiki: canvas-click-comments

Read this first. Append what you learn under "Learnings" (file:line). Do not re-verify a fact marked VERIFIED unless a test contradicts it. Facts marked UNVERIFIED come from a read-only /mycodex vet; confirm the line before relying on it, and correct this file if it is wrong.

## What we are building (v0, deliberately small)

Alt-click (long-press on a phone) or a floating "comment" button on a live canvas page opens a composer next to an element. Enter posts the comment to the bridge, which holds it on the session. The agent runs `streamweaver canvas-notes NAME`, gets the notes (and they are cleared), finds the quoted text in its own DSL file, edits it and re-pushes.

NOT in v0 (designed and cut, do not add): source-line mapping, revision ring, LCS pin successors, "shown" receipts, generation fencing, `--wait`, reply_to/peerpressure wake, images, layout inbox. Notes live in memory; a bridge restart or session close loses them (accepted).

## Decisions already made

- Notes go through their own route `POST /canvas/:name/note`. They must NOT go through `forward_to_claude` or `POST /canvas/:name/event`.
- Payload: `{text, selected_text, element_text (first ~120 chars), breadcrumb (nearest headings, kind), index (optional)}`. Server caps: text 2 KB, body 16 KB (413). Unknown session: 404.
- Drain is one locked read-and-clear on the session, exposed as a new socket command (name it e.g. `drain_notes`) beside `get_dsl`.
- Overlay lives OUTSIDE `#app-container`, beside the save-doc widget, so the 500 ms poll swap cannot destroy it or an open composer. Plain click without Alt and outside comment mode must still press buttons as before.
- "noted" toast only after a successful POST; on failure keep the draft.
- Viewer text is untrusted: print it with `inspect` on one line under a trusted header; the skill says it asks for edits to this doc only.

## Facts

- VERIFIED (read in this session): `Client#send_message` returns `messages.first` with no type check (lib/stream_weaver/canvas/client.rb:112-113). A forwarded event arriving during a request can be read as its response. This is why notes must not be broadcast to socket clients. It is an existing bug; do NOT fix it in this epic.
- VERIFIED: `Bridge#handle_push` sets html before dsl and takes no lock (lib/stream_weaver/canvas/bridge.rb:118-141). Do not depend on atomicity between them.
- VERIFIED: `bridge_server.rb` before-filter blocks non-GET with a cross-site `Sec-Fetch-Site` (about lines 94-102); a same-origin fetch from the page passes.
- VERIFIED: the page template interpolates `session_name` unescaped into `<title>` (bridge_server.rb ~293). Existing bug, tracked as disc-215. Do not widen it: any NEW place you put the session name in HTML or JS must be escaped.
- UNVERIFIED: the bridge socket dispatcher rejects unknown message types (lib/stream_weaver/canvas/bridge.rb:53), so a new command needs a new `when`.
- UNVERIFIED: the HTTP routes and socket commands run on different threads (bridge_server.rb ~595). `Session#@mutex` is private and used only for toasts (session.rb:31, 96-114); the toast read-and-clear at session.rb:109 is the pattern to copy. Expose a small public method (e.g. `add_note` / `drain_notes`) that takes it; do not make the mutex public.
- UNVERIFIED: the save-doc widget and `sw-replay.js` are mounted in `render_canvas_page` outside `#app-container` (bridge_server.rb ~313-321); `sw-replay.js` is loaded by inlining the asset. Copy that pattern for the overlay JS (new file `assets/js/sw-canvas-notes.js` or inline).
- UNVERIFIED: `sendEvent` replaces the page with "Submitted" on any control click (lib/stream_weaver/adapter/alpinejs.rb ~1015-1037); comment-mode clicks must be intercepted in the capture phase (`addEventListener(..., true)` + `stopPropagation` + `preventDefault`) before Alpine handlers see them.
- UNVERIFIED: `Client.send_message` runs a staleness guard (client.rb ~96) that can auto-restart an older bridge (staleness_guard.rb ~55). A new socket command talking to an OLD running bridge returns an error; the CLI should say "restart the bridge: streamweaver canvas-restart" rather than crash.
- Rendered text can be generated by a Proc and may not appear literally in the DSL; the skill tells the agent to resolve ambiguity before editing.

## Gotchas for every builder

- Never start, stop or restart the user's real canvas bridge, and never touch `~/.streamweaver`, in specs. Specs build a Bridge/BridgeServer in-process (see existing `spec/canvas/*`). For browser checks the coordinator boots an isolated instance; set `SW_NO_OPEN=1` on any boot.
- Git hygiene (repo is headed for open source): stage explicit paths only, never `git add -A`/`.`/`-u`; no `/Users/...` paths, personal emails or employer names in committed files; do not push. About 38 unrelated untracked files exist in the checkout: leave them alone.
- Markdown/YAML: no em dashes or en dashes anywhere you write; table separators are exactly `|---|---|`.
- Ruby first. Browser JS only where unavoidable, small, no build step, no dependencies.
- macOS: `sed -i ''` needs the empty string; prefer the Edit tool.
- Use the Read tool with offset/limit, not sed/head/tail via Bash, for file sections.

- note-store: CONFIRMED the dispatcher is a `case message[:type]` in lib/stream_weaver/canvas/bridge.rb:53-76 (the `else` at :73 rejects unknown types); `drain_notes` added beside `get_dsl`.
